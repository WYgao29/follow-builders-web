# 中文总结专用 v3 数据与网页设计

日期：2026-08-31

## 目标

将中文数据从“翻译与摘要混合”改为“只生成中文总结”。所有内容保留英文原文，中文加工字段统一为 `summaryZh`。智谱 GLM 继续由 GitHub Actions 调用，API Key 继续存放在仓库 Secret 中。网页删除中英文切换按钮，固定展示中文总结和英文原文。

本次迁移同时解决推文 `textZh` 被错误标记为“AI 简述”的问题，并降低不必要的全文翻译 Token 消耗。

## 数据契约 v3

`data/index.json` 与所有 `data/days/YYYY-MM-DD.json` 的 `schemaVersion` 从 `2` 升为 `3`。

三类内容的中文字段统一如下：

| 类型 | 保留的英文内容 | 保留的中文内容 | 删除字段 |
| --- | --- | --- | --- |
| 推文 | `text` | `summaryZh` | `textZh` |
| 播客 | `title`、`transcript` | `summaryZh` | `titleZh`、任何 `transcriptZh` |
| 博客 | `title`、`content` | `summaryZh` | `titleZh`、`contentZh` |

URL、作者、发布时间、互动数字等元数据保持不变。v3 校验器对最近数据要求非空 `summaryZh`，并拒绝重新写入上述已删除的翻译字段，从源头避免语义回退。

推文总结规则：只概括核心信息，不逐句翻译；通常 1–2 句且不超过约 80 个中文字符；保留关键人物、产品、数字和结论；忽略非关键链接、提及和标签。极短内容仍生成语义概括，但提示词明确禁止机械直译。

播客继续生成约 400 字中文要点总结。博客继续生成 2–3 句中文总结，但不再分块翻译全文。

## GitHub Actions 与 AI 加工

定时任务、手动触发、Secret 注入和自动提交仍在 `zaolangzhe-data` 的 GitHub Actions 中运行。`ZHIPU_API_KEY` 不进入代码或 JSON。

工作队列对三类内容只检查 `summaryZh`：

1. 新条目缺少 `summaryZh` 时进入 AI 队列。
2. 已有播客和博客的 `summaryZh` 直接复用，不重新调用 AI。
3. 历史 77 条推文没有 `summaryZh`，在一次性 v3 回填中生成真正的中文总结。
4. AI 返回空内容、非法 JSON 或条目映射不完整时，本轮失败且不推进状态、不提交半成品。
5. 后续定时任务只有在出现新条目或明确的待补总结时才调用 AI。

删除博客全文翻译后，常规 Token 消耗会显著下降。推文总结使用一次请求返回 `summaryZh`；不额外请求翻译。现有去重、并发限制、原子写入和数据校验继续生效。

## 历史迁移与发布顺序

迁移器负责：

- 将 v2 日分片读入内存；
- 删除 `textZh`、`titleZh` 和 `contentZh`；
- 保留现有播客、博客 `summaryZh`；
- 将缺少总结的推文加入一次性回填队列；
- 仅在所有总结成功且整个仓库通过 v3 校验后，原子写入 v3 日分片和索引。

发布采用兼容过渡，避免网页中断：

1. 先发布网页兼容版本：可以读取 v2/v3，但只展示 `summaryZh`，不再把 `textZh` 当总结；删除语言切换按钮并升级缓存版本。
2. 再合并数据仓 v3 管线并手动触发一次完整历史回填。
3. 确认 v3 数据已提交且网页读取成功后，网页可在同一变更中保持短期 v2 读取兼容；后续无需单独清理也不会展示翻译字段。

在数据 v3 回填完成前，v2 推文因没有 `summaryZh` 将临时只显示英文原文，这是有意的安全降级，优于继续把翻译冒充总结。

## 网页行为

顶部导航删除 `EN` 中英文切换按钮及其事件、偏好和状态。页面不再有语言模式：

- 推文：存在 `summaryZh` 时展示“AI 简述”块，其下展示英文原文；缺少总结时只展示英文原文。
- 播客：卡片标题使用英文标题，正文优先展示中文总结，并保留英文转录文本入口或现有详情展示。
- 博客：卡片标题使用英文标题，正文展示中文总结，并保留英文原文详情。
- 上游英文源回退时没有总结，页面正常展示英文原文并继续显示来源告警。

缓存键升级，旧缓存中的翻译字段不会参与新页面渲染。安全 URL、镜像回退、部分分片告警和可访问性行为保持不变。

## 测试与验收

数据仓测试覆盖：

- v3 合约要求 `summaryZh`，并拒绝已删除翻译字段；
- v2 到 v3 迁移会删除翻译、保留已有总结并排队缺失的推文总结；
- 推文 AI 返回的是 `summaryZh` 而非 `textZh`；
- 博客不再执行全文分块翻译；
- 空总结会阻止状态推进和文件提交；
- 完整仓库无跨日重复且索引计数一致。

网页测试覆盖：

- 顶部不存在语言切换按钮；
- “AI 简述”只读取 `summaryZh`，绝不读取 `textZh`；
- 英文原文始终可见；
- v2 兼容期缺少 `summaryZh` 时只显示英文；
- v3 日分片、缓存升级、镜像回退和浏览器冒烟测试通过。

上线验收：GitHub Actions 完成 v3 回填并提交；线上索引与日分片均为 schema 3；所有 77 条历史推文、3 条播客和 4 篇博客具有非空 `summaryZh`；JSON 中不存在被删除的翻译字段；GitHub Pages 部署成功。

## 非目标

- 不把 AI 调用迁移到本地。
- 不更换智谱模型或 Secret 管理方式。
- 不生成中文全文、中文标题或双语切换。
- 不修改内容聚合范围、日期分片策略或网页视觉主题。
